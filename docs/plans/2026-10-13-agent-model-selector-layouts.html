Agent and model selector: layout options

Nine layouts drawn from tools on the market, each judged against AO's design guide. My picks are at the top.

Why today's picker reads as the Codex / ChatGPT app

  • A strip of brand-icon tabs across the top of a rounded popover.
  • An effort slider with a round thumb.
  • One bespoke popover that no other AO surface uses. The guide says model, agent and mode choices "must not invent bespoke pills or popovers" and should share the New Task and Settings menu.

What AO's product thinking asks for

  • The session is the object. The agent is a property of the session, not the app's identity.
  • A switch is an intervention. It hands work to another agent, so it must say what carries over.
  • Same in chat and terminal. They are two views of one session.
  • Shared lists, quiet chrome. Adjacent rows on one surface; colour only for state.
  • Scales. AO lists 30+ agents; a few are ready on any machine.

My picks

  • 1. A — One menu, three rows. The base. It is AO's own New Task selector, so chat, terminal, New Task and Settings finally match.
  • 2. H — Setups first, folded into the top of A. Most switches are between the same two or three setups; favourites are already built.
  • 3. C — Command palette as the keyboard path to the same list. No new visual surface.
  • Borrow from F: the one line saying what the handoff carries. Skip the dialog itself.

Not recommended as the main control: B, D, E, G, I. Reasons are with each.

What I would build

  • A + H as one menu. Setups on top, then Agent, Model, Effort rows, then the toggles (Fast, auto-compact). Built from the shared option menu.
  • Keep the notice strip above the composer ("Next message goes to …") and add F's line on what carries over.
  • C on a shortcut for the same list.
  • E later, read-only: hand-off history in the inspector.

What this drops: the icon tab strip, the slider and its Ultra animation. Ultra and Ultracode become the last effort row, and can keep the animated label on the chip.
