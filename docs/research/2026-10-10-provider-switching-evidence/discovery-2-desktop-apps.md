# Discovery 2: desktop and web GUI apps that orchestrate or wrap multiple coding agents

Research date: 2026-10-10/11. Method: `gh api` (repo metadata, file trees, file contents, code search) plus WebSearch/WebFetch of official docs. No repo was cloned and no code was run. Excluded by instruction: Orca, T3 Code, Conductor, Superset, Agentastic, Synara. Also not listed: `OrchestratorInc/agent-orchestrator` (that is AO itself).

Class key: A = cross-agent handoff (same task/thread/workspace continues on a different agent, context carried); B = model/provider picker inside one agent/harness; C = parallel/side-by-side, no conversation handoff; D = no switching; U = unclear.
V = VERIFIED (seen in source or official docs, URL/path given). I = INFERRED.
"Stars" and "pushed" are GitHub values read on 2026-10-10.

## Details (A and B products)

### Jean (coollabsio/jean) - A, VERIFIED
- What it is: Tauri desktop app (also a headless server) for Claude/Codex/Cursor/OpenCode/Pi/etc. CLIs across git worktrees. 1.3k stars, created 2026-01, pushed 2026-10-10.
- How switching works: a session has a list of `runs`, each tagged with its backend. `should_inject_handoff(previous_backend, current_backend)` fires when the previous completed run's backend differs from the current. Jean then builds history from its own run log (not the provider's) and prepends a hidden block to the user's next message: `<jean_provider_switch_handoff> ... </jean_provider_switch_handoff>` (`prepend_hidden_handoff`).
- What is carried: last 40 runs, capped at 60,000 characters (`HANDOFF_HISTORY_RUN_LIMIT`, `HANDOFF_HISTORY_MAX_CHARS`), rendered as `User:`/`Assistant:` lines; when no text, `[tools used: a, b]`; "[truncated older Jean history]" marker; falls back to run metadata when the message window cannot be loaded (assistant bodies then placeholder as `[assistant reply via backend/model; status=...; full body unavailable in handoff fallback]`). Thinking blocks and tool outputs are not carried.
- Prompt (user-editable preference `provider_switch_handoff`, default in `src/types/preferences.ts`): "You are continuing a Jean chat session after the user switched AI backends. Jean-local history is the source of truth because provider-owned server history may be incomplete after backend switches... Do not mention this hidden handoff unless it is directly relevant." Placeholders `{previous_backend}`, `{current_backend}`, `{history}`.
- Also handles Claude profile/account switches within Claude (`should_inject_claude_profile_handoff`).
- Delivery timing: at next send after the switch, invisible to user. UI: backend/model picker in the chat toolbar (`src/components/chat/toolbar/BackendModelPickerContent.tsx`).
- Sources: `jean-core/src/chat/handoff.rs`, `src/types/preferences.ts` (DEFAULT_PROVIDER_SWITCH_HANDOFF_PROMPT), https://github.com/coollabsio/jean

### Kanna (jakemor/kanna) - A, VERIFIED
- Web UI for Claude, Codex, Cursor, Grok Build, Pi; "switch between ... from the chat input" (README).
- How: `src/server/handoff.ts` header: "When a chat's provider changes, the new harness starts a fresh native session that knows nothing about the conversation. We render the Kanna transcript (the source of truth) to a plain-text record and prepend it, wire-only, never persisted, to the first prompt sent to the new harness."
- Budget: 100k tokens (4 chars/token). Tool inputs/results outside the most recent 100k-char window are elided if over 2,000 chars with a pointer `entry <id> in the transcript JSONL`; older turns dropped wholesale on a user-prompt boundary so tool calls keep their results; error results capped at 2,000 chars; hidden and sub-agent entries skipped.
- Preamble: "This conversation is being handed off to you from another coding agent (<from>). You are taking over mid-conversation." The transcript sits in `<handoff_transcript>` as read-only record, plus the full JSONL path so the agent can read omitted parts. A different preamble is used for same-provider `session_restore`.
- Side effects (`src/server/agent.ts` around line 1816): clears the native session token, stops the warm Codex app-server session ("would silently resume the old thread on switch-back"), closes Pi chat, and appends a `handoff_boundary` entry (with stats: entries, included, elided tool results, approx tokens) to the visible transcript.
- Sources: `src/server/handoff.ts`, `src/server/agent.ts`, https://github.com/jakemor/kanna

### Atlas (pacifio/atlas) - A, VERIFIED
- Tauri app, "Source control for coding agents"; created 2026-05, 9.6k stars. Runs Claude Code, Codex, own agent, any ACP registry agent. README: "shared memory so switching agents mid-task doesn't mean starting over".
- How (`src/features/chat/lib/switch-agent.ts`): a session is paired with one agent for its lifetime, so switching means a new session. Setting `agentSwitchBehavior`: `reset` (default; clear and start over), `new-tab` (keep old tab, open a new tab on the new agent), `handoff` (switch in place and attach the previous conversation to the composer as a "past session" chip so the new agent receives it with the next message). Toast: "<A> conversation attached. Your next message hands it to <B>."
- Busy chat is never switched in place; a fresh tab is opened. A chat whose first message is still waiting on a bind ("starting") is switched in place and the held message is carried.
- Optional `rememberBeforeSwitch`: if the leaving agent advertises `/remember`, Atlas sends that first so it records learnings in shared memory, then switches; the remember turn is excluded from the attached transcript (`endBeforeRemember`).
- Entry points: Alt+/ cycle, composer agent pill, "+" menu.
- Sources: `src/features/chat/lib/switch-agent.ts`, `docs/reference/configuration.md`.

### Agent of Empires (agent-of-empires/agent-of-empires) - A, VERIFIED
- TUI + web session manager (MIT, 3.3k stars, created 2026-01) for Claude, OpenCode, Codex and ACP agents; "structured view" = ACP chat, otherwise terminal.
- CLI `aoe acp switch-agent <session> <target> [--model]`: "Switch an agent session to a different ACP agent, keeping the transcript... The new agent starts fresh... Handy for returning to claude after a rate-limit handoff to codex." (`src/cli/acp.rs`). Also `switch-provider` (api/bedrock/vertex, model resets to the new provider's default).
- Web: `web/src/components/acp/SwitchAgentModal.tsx` "Hands the session to another ACP agent, then prefills (never sends) a handoff message with a recap from before the switch and any prompt the old agent never processed. The rate-limit trigger prefers codex and frames the recap as a handoff." The current agent stays listed but disabled.
- Context: `src/acp/context_primer.rs` builds a markdown "Prior structured view context" from the persisted event log: max 24,000 chars / 20 turns, bulk tool args (file bodies, patches, output) dropped, only identifiers (path, command, pattern, ...) kept, assistant tail capped at 6,000 chars, trailing "## Current request: Continue from where we left off." plus `unprocessed_prompt` when the session ended rate-limited before the agent processed it. A banner component `ContextPrimerBanner.tsx` shows it.
- State record `AgentSwitchInfo { from, to, reason, switched_at }` (`src/acp/state.rs`).
- Also session fork (same agent, new session) in `docs/guides/session-resume.md`; a fork under a different agent is explicitly refused.

### Maestro (RunMaestro/Maestro) - A, VERIFIED
- Electron app orchestrating Claude Code, Codex, OpenCode, Factory Droid, Copilot CLI, etc.; non-interactive batch mode per turn; 3.4k stars, AGPL-3.0, active 2026-10-10.
- "Context: Send to Agent" (tab menu or Cmd+K): extract context from source tab, groom it with an AI pass, create a new session/tab on the target agent, initialize it with the groomed context (`src/renderer/hooks/agent/useSendToAgent.ts`). Modal shows searchable agent list, token estimate, "clean context" toggle (default on; off = verbatim). If the target is busy: "Queue for Agent" or "Force Send".
- The groomer prompt (`src/prompts/context-transfer.md`) says: preparing a conversation for transfer from {{sourceAgent}} to {{targetAgent}}; preserve code changes, decisions, file paths, errors, config, cwd, git branch; remove agent-specific slash commands (/clear, /compact), tool names and invocations; "Summarize the current state clearly for the new agent".
- Related: Cross-Agent Mentions (`@agent`): forwards a window of the transcript (full by default, narrowed by prose hints like "last 5 messages") to another agent as an ephemeral read-only consult and streams the reply back with attribution. Docs: docs/cross-agent-mentions.md, docs/context-management.md ("Start a task in Claude Code, then hand off to Codex for a different perspective").

### Paseo (getpaseo/paseo) - A, VERIFIED
- Open-source desktop/mobile/web "agentic development environment", 20.4k stars. README: "One interface for Claude Code, Codex, Copilot, OpenCode, Pi, Antigravity, and Muse Code agents"; "Agents ... can create worktrees, launch other agents, and talk to them, across providers."
- `skills/paseo-handoff/SKILL.md`: user says "handoff" / "hand this to ..."; the current agent writes a self-contained briefing (Task, Context, Relevant files, Current state, What was tried, Decisions, Acceptance criteria, Constraints), calls `list_profiles` (profiles have `notes` for matching work to provider), then `create_agent` titled `[Handoff] <task>` with the briefing as initial prompt, optionally in a new worktree. "The receiving agent starts with zero context." Detach is a user gesture.
- Also `packages/server/src/server/agent/provider-session-import.ts` imports an existing provider-native session (resume) into a Paseo agent timeline.

### Kandev (kdlbs/kandev) - A, VERIFIED (specs marked "draft"; code exists at `apps/backend/internal/agent/runtime/dynamic/conductor.go`)
- Kanban + chat orchestrator, AGPL-3.0, 915 stars. Task sessions with agent profiles; ACP, Codex app-server, OpenCode, Copilot, Amp adapters.
- Dynamic Agent Routing (`docs/specs/agents/requirements/dynamic-agent-routing.md`, updated 2026-10-08): a "dynamic" profile has an ordered candidate list of concrete profiles (Claude, Codex, OpenCode, ...). On transient or hard provider errors (usage limits etc.) the conductor moves to the next candidate; "The session, conversation, and logical profile shall remain unchanged"; a replacement is never presented as a new participant. Also an unclassified-failure threshold fallback (2-10 consecutive failures).
- Design (`docs/specs/agents/system-design/dynamic-agent-routing-01.md`): "Switching to another concrete profile always creates a fresh downstream ACP session. A resume token from one concrete profile is never supplied to another. Before the replacement prompt, Kandev creates a bounded continuation package from the task description, current workflow step, user messages and durable conversation summary, tool/result summary, repository status and diff summary, active plan or task metadata, and the failure and route reason. If the failed agent is still responsive, the conductor can request a handoff summary. Failure to obtain one cannot prevent fallback." The replacement prompt "tells the agent that it is continuing existing work, what was completed or uncertain, what caused the switch, and which actions must not be repeated without verification." Chat stream events `session.route_changing`, `session.route_changed`, `session.capabilities_replaced`; each turn records provider/model label and `route_generation`.
- Simpler path: new session on same task uses `apps/backend/config/prompts/session-handover.md` ("This task has had N previous session(s)... Any code changes are already present in the working directory... Do not repeat work") plus the task plan, bounded by `planinjection`.
- Draft `harness-session-continuity.md`: user-selected `continue_from_history`; bounded snapshot persisted before native creation; delivery checkpoint with prepared/accepted/consumed/uncertain states; opening a session never authorizes context continuation; uncertain delivery blocks automatic resend.

### Helix (helixml/helix) - A, VERIFIED
- Private "agent fleet" platform; each agent in a GPU desktop container running Zed as UI; 818 stars.
- Docs https://helix.ml/docs/guide-switch-agent : change agent on a running spec task from the chat header; confirmation dialog; "the new agent receives the full conversation history from the previous one" and inherits tools/config; optional pre-fork checkpoint commit "chore(fork): pre-fork checkpoint"; fork divider, read-only parent history, "Forked from" badge; parent paused, switch is one-way.
- Source: `api/pkg/server/session_switch_agent_handlers.go` describes a second mode, in-place switch: same session and desktop container, settings daemon rewrites Zed's agent_servers config, Zed hot-reloads, Helix "delivers a fresh thread ... repopulated with the prior thread's transcript"; clean Zed restart as fallback. Fork-and-pause path in `session_fork_handlers.go`.
- For model-only changes, a separate per-task execution-settings change keeps the same agent.

## Ideas worth stealing

1. **Make the handoff text a wire-only prefix and keep the product transcript as the source of truth** (Jean, Kanna): provider-native history is incomplete or non-portable, so render from the app's own log; never persist the injected text; record a visible boundary entry (Kanna `handoff_boundary` with stats; AoE `AgentSwitchInfo`).
2. **Budget with a user-prompt boundary** (Kanna): ~100k tokens, elide large old tool IO with an id pointer, drop oldest turns on user-prompt boundaries so tool calls keep results, point the new agent to the full JSONL path on disk. Jean uses 40 runs / 60k chars; AoE 20 turns / 24k chars and strips bulk tool args.
3. **Prefill, do not auto-send, for TUI targets** (AoE, Agentrium): stage the brief in the composer; never type into an unknown PTY state (trust/login prompts).
4. **Include the in-flight prompt the old agent never processed** (AoE `unprocessed_prompt`), and for rate-limit-driven switches name the reason (AoE, Kandev route reason).
5. **Switch policy as a setting** (Atlas `agentSwitchBehavior` = reset / new-tab / handoff) and never switch a busy chat in place (Atlas opens a new tab; Kandev defers successor launch).
6. **Offer a pre-switch memory save** (Atlas `/remember` before switching; Kandev asks the failed agent for a handoff summary but never blocks on it).
7. **Persist before delivering, track delivery state** (Kandev: snapshot persisted before native creation; prepared/accepted/consumed/uncertain; uncertain blocks auto-resend). Kanna: clear the native session token and kill warm sessions (Codex app-server) so a later switch-back does not silently resume the stale thread.
8. **Never reuse a resume token across agents** (Kandev), and treat same-agent account/profile changes as handoff-capable too (Jean Claude profile handoff, Happy compatible vs incompatible switch).
9. **Tell the new model the truth** (Happy `ModelSwitchModule`: system notice that hidden prior conversation exists, excerpt of first/last messages, plus a history-reading tool; Kandev: "which actions must not be repeated without verification"; Jean: "do not claim you lack prior context").
10. **Agent-authored briefing as an alternative path** (Paseo handoff skill, Sculptor handoff skill, Amp handoff with editable draft): good for "what was tried / decisions" that a mechanical transcript misses; combine with the mechanical history.
11. **Native session conversion** (Continuo): translate tool vocabularies and write the target's own session file so the target resumes natively with full history; reasoning traces are lost; choose full transcript vs brief by the target model's real context limit.
12. **Know why others restrict it** (CodePilot lock-after-first-run lessons: cache reset, partial history seen, optimistic UI vs actual route; Nimbalyst blocks agent-provider switching to keep SDK state coherent). Atomic server-side validation of the new route and honest display of cache/cost impact are worth copying.
13. **Git state at switch time** (Helix pre-fork checkpoint commit; Agentrium same vs forked worktree; Maestro cleaning agent-specific slash commands from transferred text).
