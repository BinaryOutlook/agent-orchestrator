## Kangentic

1. **What.** Desktop Kanban board that spawns coding agents per card in PTYs, 15 CLIs. https://github.com/Kangentic/kangentic, site kangentic.com. 126 stars, AGPL-3.0, created 2026-02-22, pushed 2026-10-08, 4 open issues, open source. Terminal UI only (xterm), plus a mobile companion. VERIFIED (GitHub API, README).
2. **Trigger.** Manual and implicit: moving a task to a column with a different `agent_override`. `resolveTargetAgent()` sets `isHandoff = taskAgent !== null && taskAgent !== agent` (`src/main/transition-engine/agent-resolver.ts` line 55). Not tied to any limit. A task with its own `agent_override` never hands off on column moves. VERIFIED.
3. **Same thread or new session.** New session on the target agent, same task card and worktree. The old session is suspended first (docs/transition-engine.md, Priority 3a). Model and effort overrides are cleared because they are model-specific. VERIFIED.
4. **Source.** The source agent's native session history file, found by `sourceAdapter.locateSessionHistoryFile(agent_session_id, cwd)` in `src/main/ipc/helpers/agent-spawn.ts` (about lines 335-355). Examples in docs/handoff.md: `~/.claude/projects/<slug>/<id>.jsonl`, `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`, `~/.gemini/tmp/<dir>/chats/session-<id>.json`. Cursor, Copilot, Oz, Ollama, Goose return none. VERIFIED.
5. **Content and shape.** Nothing is copied, so there are no budget numbers. The target reads the file itself. Claude as target also gets an MCP history tool (docs say `kangentic_get_transcript`, code says `kangentic_get_session_history`; the docs are stale). Per-adapter `transcript-cleanup.ts` files still exist for TUI scrollback but the transcript audit says cleaned scrollback is not used as a fallback. VERIFIED.
6. **Framing** (`buildHandoffXml`, `src/main/agent/shared/prompt-xml.ts`): "You are continuing work on this task that was previously handled by Claude Code." and "Read the prior session history for context on what was done, decisions made, and current state." Fallback: "No session history file is available. Check `git log` for prior changes on this branch." Then a `<handoff_context>` block with `<source_agent>` and `<session_history_path>`. VERIFIED.
7. **Delivery.** `handoffPromptPrefix + "\n\n" + prompt` becomes the initial prompt of a fresh target process (`src/main/transition-engine/transition-engine.ts`, lines 464-468). The column's auto message is typed into the PTY afterwards by `TerminalSubmitScheduler`. VERIFIED.
8. **Failure.** If preparation throws it logs "continuing without context" and still spawns. If the spawn throws it logs and returns. Audit row in a `handoffs` table (from/to session, agents, path, trigger `column_transition`), target session filled in after spawn. No rollback. VERIFIED.
9. **UI.** Card shimmer with phases `packaging-handoff`, `detecting-agent`, `starting-agent`. Per-column toggle "Session history passthrough" (`handoff_context`). Docs say default OFF; code uses `toLane.handoff_context !== false`, which is on unless set false. They disagree. Turning it off in a review column gives an independent reviewer. VERIFIED.
10. **Maturity.** Active, no open handoff bugs. Docs show a design reversal: `docs/session-lifecycle.md` still describes a `HandoffOrchestrator` that packaged transcript, git diff and metrics into `handoff-context.md`; `docs/handoff.md` and the code replaced it with the pointer, and a code comment says a future `buildHandoffPlan` might "ask the outgoing agent to author its own handoff summary".
11. **Copy / avoid.** Copy: a handoff audit table; a per-column opt-out for independent review; the `git log` fallback. Avoid: sending only a path (no budget, no cleaning; Codex rollouts are noisy and the agent may not read them).

## Codeg

1. **What.** Multi-agent coding workspace (Tauri desktop, server, Docker) speaking ACP to many agents. https://github.com/spacering-net/codeg, docs docs.codeg.app. 3,881 stars, Apache-2.0, created 2026-02-09, pushed 2026-10-10, 292 open issues. Chat UI over ACP, not a TUI. VERIFIED.
2. **Trigger.** Manual. The user `@`-mentions an old session; it serialises as `[title](codeg://session/<conversation_id>)` (`src/components/chat/composer/suggestion/adapters.ts`). The README line "hand it to a different agent" is this mention, not a switch. Docs: "Referencing a session doesn't resume it, and doesn't touch it." (https://docs.codeg.app/guide/aggregation). VERIFIED.
3. **Same thread or new session.** The mention goes into whichever chat the user is in, on whichever agent. The old session is untouched. Resuming an imported session reconnects its original agent only ("an imported Codex session resumes with Codex"). No in-place provider switch. VERIFIED (docs page via fetch).
4. **Source.** Codeg's DB row (`external_id`, `agent_type`) plus a parse of the agent's on-disk transcript, with an 8 s parse timeout and 4 concurrent parses (`src-tauri/src/commands/session_info.rs`). VERIFIED.
5. **Content and shape.** Tool `get_session_info(session_id, max_messages)` returns title, agent, status, model, branch, workspace, message count, token stats and optionally a compact recent-turns view. Constants: `DEFAULT_MAX_MESSAGES = 20` (`src-tauri/src/acp/delegation/companion.rs`), `MAX_SESSION_MESSAGES = 200` (`src-tauri/src/acp/session_info.rs`), `PER_TURN_CHARS = 1_500`, `OVERALL_CHARS = 16_000`, 16 tool names per turn at 64 chars. Walked newest first; the newest turn is always kept; older turns drop and `truncated: true` is set. Included: text and thinking blocks, role, tool names. Excluded: tool results, images, raw turns. The original first request is not pinned. VERIFIED.
6. **Framing.** It sits in the MCP tool description (`delegation/tool_schema.json`): a mention "IS the user explicitly pointing you at that session... call it whenever what that session is about or what happened in it matters to the request (e.g. to continue its work...)". VERIFIED.
7. **Delivery.** Pull. The prompt carries only the link; the agent calls the `codeg-mcp` companion, which asks the Codeg broker over a socket. Setting "Get session info" is on by default; needs an agent that forwards MCP. VERIFIED.
8. **Failure.** A missing id returns `found:false` with a note, not an error. A parse timeout returns metadata without messages plus a note. Read-only, so nothing to roll back. VERIFIED.
9. **UI.** `@` panel rows with agent icon, status and branch; inline session badge; import-sessions window. VERIFIED.
10. **Maturity.** Large user base. I saw no open issue on session mention; open issues #544/#545 say an `@<agent>` mention does not delegate (a different feature, `delegate_to_agent`). Fork (`src-tauri/src/acp/fork.rs`, ACP `session/fork`) is same-agent only.
11. **Copy / avoid.** Copy: a hard-budget, newest-first pull digest is cheap and safe; the reference is plain text so copy/paste and draft restore keep it; "agents cannot see each other's stores, but Codeg can, so it brokers". Avoid: calling this a handoff; 16k chars with no pinned original request, and the new agent decides whether to look.

## Clinch

1. **What.** macOS terminal (Warp fork, AGPL-3.0) for Claude Code and Codex sessions. https://github.com/elliot-ylambda/clinch-terminal, clinch.sh, Show HN https://news.ycombinator.com/item?id=49353724 (6 points). 6 stars, created 2026-06-29, pushed 2026-10-10, 14 open issues. Terminal UI only. VERIFIED. Other "clinch" repos are unrelated.
2. **Trigger.** Manual footer button "Transfer to Codex / Claude Code". Not automatic. VERIFIED (`app/src/terminal/view/use_agent_footer/mod.rs`, `UseAgentToolbarEvent::TransferAgent`).
3. **Same thread or new session.** New tab, fresh target process. The source agent and tab are untouched ("leaving the source agent and its tab untouched", doc comment on `open_cli_agent_transfer_in_new_tab`). Sidebar shows fork and transfer ancestry (PR #82). VERIFIED.
4. **Source.** Native transcript path or session id captured by Clinch's managed hooks in `~/.claude/settings.json` and `~/.codex/config.toml`. With only an id it builds a search hint (`$CLAUDE_CONFIG_DIR/projects/**/<id>.jsonl`, `$CODEX_HOME/sessions/**/rollout-*-<id>.jsonl`). If neither is known it toasts "The current agent has not reported a session ID or transcript yet." PR #77 fixed a dead button on panes where the user typed `codex resume <uuid>` by hand, because Codex sends no hook event until the next prompt. VERIFIED.
5. **Content and shape.** No content copied, no budget. The prompt lists previous session ID, transcript path and previous working directory.
6. **Framing** (`build_cli_agent_transfer`): "Start off by continuing where the last {Claude Code|Codex} agent left off. Here's how to find the conversation." and "Read the prior conversation first, inspect the current working tree, and continue the unfinished work rather than starting over." VERIFIED.
7. **Delivery.** A launch command with the shell-quoted prompt as the CLI argument: `claude --dangerously-skip-permissions '<prompt>'` or `codex --dangerously-bypass-approvals-and-sandbox '<prompt>'`. So the target starts with permission checks off. VERIFIED.
8. **Failure.** Toasts for missing shell type or session id. Source is untouched, so no rollback. VERIFIED.
9. **UI.** Footer button that is disabled until an id exists; new tab; ancestry in the sidebar.
10. **Maturity.** One-person project. Already hit one handoff bug (PR #77).
11. **Copy / avoid.** Copy: leave the source running and untouched; capture session ids through provider hooks; show ancestry. Avoid: bypass-permissions flags by default; a pure pointer; Codex has no id until its first hook event.

## Continuo

1. **What.** macOS menu-bar app (Swift) with a CLI. https://github.com/yoavf/continuo, https://usecontinuo.dev, v0.3.1. MIT, 10 stars, created 2026-07-07, pushed 2026-09-02, 0 open issues. Open source. Converts then opens the session in Terminal, iTerm2, Ghostty, CMUX, Codex desktop or Claude Desktop. VERIFIED.
2. **Trigger.** Manual (picker, hotkey Option+Command+S). "Nothing runs in the background — sessions are converted only when you ask." It names hitting a model's limits as a use case but has no detection. VERIFIED.
3. **Same thread or new session.** New native session in the target (a "mirror"). Sources are read-only. A continued mirror is never rewritten; a fresh one is created. Mirrors are tracked in `bridge-state.json` and it "refuses to overwrite anything it doesn't own". VERIFIED (README, `Sources/AgentSyncCore/SyncEngine.swift`).
4. **Source.** Native session files (`~/.claude`, `~/.codex`, OpenCode's `opencode.db`) parsed by per-agent adapters into a canonical session. An optional on-device LLM (Apple Intelligence) writes titles and the summary. VERIFIED.
5. **Content and shape** (`HandoffBrief.swift`, `TextBounds.swift`, `SyncEngine.swift`).
   - Modes: auto, full, bookends, handoff. Auto picks the brief "exactly when a full render would have to truncate".
   - Full: byte budget is 60% of the target model's context window times 3.4 chars per token, capped at 2,000,000 bytes (comment: "a ~300KB render measured 111k tokens in Codex"). Window sizes come from models.dev, bundled and refreshed weekly. Oldest events drop; tool results whose call was cut are dropped.
   - Bookends: first 4 and last 8 user/assistant messages, 4,000 chars each, with a notice stating how many middle messages and tool events were omitted.
   - Handoff: brief plus the last 8 messages, tools dropped. The brief holds the original goal (first user message, 1,200 chars), an optional AI summary, counts, "Recent focus" (last 6 user messages at 300 chars) and the source file location. The summarizer input is evenly sampled (up to 50 entries, 12,000 chars). If the tail does not end on a user turn, it appends "My latest request, repeated so you can continue from it".
   - Excluded: provider-local noise, injected context, encrypted reasoning, usage, system prompts, file snapshots.
6. **Framing.** "[Continuo handoff brief] This is a compacted continuation of the ... conversation ..."; "Full history: <path> — read it directly if you need details older than the messages below."; "Pick up from the latest exchange below, using the current repository state as ground truth." Bookends notice ends: "Continue from the latest exchange below, using the current repository state as ground truth." VERIFIED.
7. **Delivery.** Not a prompt. It writes the target's native session file (OpenCode through the official `opencode import`) and launches the resume command or deep link. The brief is the first message of the written session. VERIFIED.
8. **Failure and idempotency.** Mirror ownership is reserved before writing, the latest uncontinued mirror is reused, and `auto` fails with a message when nothing fits instead of silently cutting. VERIFIED.
9. **UI.** Menu-bar picker, a continue panel with the target agent and a "how much to carry over" choice, settings for default target models and destinations.
10. **Maturity.** Tiny, single maintainer, no issue history. The author compared it to Skillsync in the HN thread. The test file for the engine is 79 KB.
11. **Copy / avoid.** Copy: the full / bookends / brief ladder; a budget set as a percentage of the TARGET model's real window; always end on the user's latest request; evenly sampled LLM summary input; the brief carries a pointer to the full file; pin the first request as "Original goal". Avoid: writing undocumented native formats (same risk as txcript).

## Skillsync / txcript

1. **What.** Skillsync (YC W26, founders Nars and Nishant, skillsync.com) sells a Mac app, CLI and MCP; the open core is txcript, "Pandoc for AI chats". https://github.com/skillsynchq/txcript. 155 stars, Apache-2.0, created 2026-06-25, pushed 2026-09-29, 27 open issues. Rust library, CLI, WASM and npm. The CLI has a pager viewer and a crop editor; the desktop app is closed. VERIFIED.
2. **Trigger.** Manual: `txcript continue <id> --with codex`. The HN post lists "when you hit a usage limit on one and want to keep going on another" as a use, with no automation. VERIFIED (README, HN).
3. **Same thread or new session.** New native session in the target harness. "What is written is always a copy; the source session is never modified or removed." Same harness resumes in place. VERIFIED (`docs/usage.md`).
4. **Source.** The source agent's own session files (Claude Code, Codex, OpenCode, Cursor CLI and desktop, pi, Grok, Antigravity, Hermes, Amp, plus live Claude Chat and ChatGPT accounts), parsed into `Transcript<Common>` with messages, thinking, tool use and results, images, metadata, usage. VERIFIED.
5. **Content and shape.** The whole session by default. I found no size budget. The user can narrow with `continue <id>#range` or the `crop` editor, where a tool call and its result are always removed or restored together. Lost: Codex `encrypted_content` reasoning, sandbox and approval context, system prompt (the target supplies its own), unmodelled records. Codex `apply_patch` mapping is best-effort. VERIFIED (`docs/formats/codex.md`, `claude-code.md`).
6. **Framing.** None. History is replayed as native structured turns, not as wrapped text. INFERRED from design.
7. **Delivery.** Writes the session into the target's store, then launches its resume command (default per harness, overridable with `TRANSCRIPT_<HARNESS>_RESUME_CMD`, e.g. `codex resume {id}`). VERIFIED.
8. **Failure.** Writing native formats is fragile. Issue #59 (closed): replay used `Bash` and `Edit` tool names Codex rejects, so the resumed session broke. Issue #68 (open): an interrupted session ends in a `tool_use` with no `tool_result`, and Claude's API returns HTTP 400 on resume. Codex needs `model_provider: "openai"` in `session_meta`. Claude's `tool_use.input` must be an object (non-objects are wrapped). Ids are deterministic UUIDv5. Hostile content such as `</local-command-stdout>` is escaped. The docs call Claude's format "officially unstable". VERIFIED.
9. **UI.** CLI picker with match-kind labels, pager with filters, crop editor, MCP server (read-only). The app offers "Continue on any agent" (AlternativeTo listing, CLAIMED).
10. **Maturity.** Credible: a YC company, a 68-point Launch HN, frequent releases, a test per harness (`tests/integration/cross_harness.rs`). Open bugs are about resume breakage and new harness requests. The HN thread asked about quality loss between models; I saw no answer in the first 12 comments.
11. **Copy / avoid.** Copy: a typed canonical model; tool call/result pairing invariants; crop before continue; always write a copy; per-harness fixtures. Avoid: depending on vendor file formats; converting with no token budget (a long Claude session may not fit a smaller Codex window).

## SpecWeave 3

1. **What.** Spec-first AI dev framework (CLI, skills, hooks, docs). "SpecWeave Studio" is a separate private pilot app. https://github.com/anton-abyzov/specweave, https://spec-weave.com. 165 stars, MIT, created 2025-10-25, pushed 2026-10-10, 13 open issues. No chat UI of its own. VERIFIED.
2. **Trigger.** Automatic after `specweave auto-handoff on` (docs-site/docs/guides/auto-handoff.md). A `Stop` hook runs `specweave usage-guard` and compares the fullest unreset window (5-hour, weekly or spend) with a threshold, default 90, `--at N`. This fires BEFORE the limit, at the end of a turn. A `StopFailure` hook with matcher `rate_limit` (Claude Code and Grok Build) writes the handoff itself when the limit already hit, at most once per session per 5 hours. Codex has no failure hook. Signals: Claude Code's status-line percentages saved by `specweave statusline`, with desktop app samples or the `~/.claude.json` cache as fallbacks; Codex's `rate_limits` records in its own session log. A Codex plan with credits is not stopped unless the burn rate leaves under 60 minutes. Asked once per window. Silent outside a SpecWeave project. Manual: say "hand off" or run `specweave handoff`. VERIFIED (docs; `src/core/session/usage-guard.ts` exists but I did not read it).
3. **Same thread or new session.** New session in any other tool, account, machine or cloud session. The hook blocks the stop and tells the model to run the handoff command, tell the user to say "pick up" elsewhere, and stop. A human starts the receiver. Not a thread continuation. VERIFIED.
4. **Source.** Tool-written files, not a transcript. `handoff.md` beside the increment (where it stopped, next step, files touched), `ledger.jsonl`, the pushed branch and a snapshot of uncommitted edits on `specweave-handoff` and `wip/<branch>`. Secrets scrubbed (`handoff-secret-scrub.ts`). The docs: "None of them can read another tool's private transcript, so SpecWeave keeps what matters in git" (cross-tool-handoff.md). VERIFIED.
5. **Shape.** One page, fixed order: Where I left off, Done / Pending, Decisions, Files touched, Next steps, Resume (`src/core/session/handoff-doc-format.ts`, "Doc format v2"; `<!-- keep -->` blocks survive regeneration). Local checkpoints after every Stop, throttled to once per 5 minutes per worktree and session, stored in `~/.specweave/checkpoints/`.
6. **Framing.** The hook tells the model to run `specweave handoff --reason "usage at 92% of the 5-hour limit"`, tell the user to say "pick up", and stop. The doc carries a per-tool resume command matrix. VERIFIED.
7. **Delivery.** `specweave pickup` in the next tool, triggered by a rule in `AGENTS.md`. It fetches the last handoff, fast-forwards the branch, applies edits only if the checkout is clean (else it says what to do and changes nothing) and prints the next task with acceptance criteria. Claude Code's SessionStart hook prints the same summary.
8. **Failure.** The 90% default "leaves about a tenth of the window for the handoff turn". A local checkpoint covers a sender that died; `pickup` prints a "Local checkpoint:" line when one is newer than the last handoff. `on` is idempotent, `off` restores the old status line. Inside Studio the hooks only checkpoint. A `checkpoint-only` mode exists. Codex needs the hook trusted by hand. Docs lag in places: `studio-architecture.mdx` still says 3.0.6 does not stop at a limit, while the auto-handoff guide says later versions hand off at the threshold. VERIFIED.
9. **UI.** CLI, an HTML timeline report (`specweave report`), and Studio. Studio docs: "You can also switch a thread to another provider yourself. Studio passes a budgeted part of the conversation to the new agent... Studio does not yet switch on its own when a provider reaches a usage limit." (docs-site/docs/overview/studio.mdx). That is real thread-level switching, but its source and budget numbers are not public (CLAIMED).
10. **Maturity.** Active, 165 stars. Visible issues are internal task mirrors, nothing about handoff bugs. The "automatic handoff at 90%" claim is VERIFIED, with the correction that it moves repo state and a document, not the conversation.
11. **Copy / avoid.** Copy: act before the limit from a percentage, once per window; a failure hook as backstop; checkpoints so a crashed sender is recoverable; secret scrubbing; refusing to apply to a dirty checkout. Avoid: using the model to run the handoff at the moment quota is scarcest; usage numbers from undocumented app files (they admit samples can miss a jump); no conversation context.

## Sno Station

1. **What.** "Claude Code and Codex working as one squad": shared encrypted memory (`apps/mem-*`), Sno Reach (agent-to-agent messaging in bash and tmux, "no daemon", mail-style cards), and 31 skills in a second repo. https://github.com/sno-ai/sno-station (500 stars, Apache-2.0, created 2026-09-19, pushed 2026-10-10, 0 open issues) and https://github.com/sno-ai/sno-station-skills (122 stars, created 2026-10-01). The `sno` CLI source is not in either repo. Terminal agents only. VERIFIED.
2. **Trigger.** Two paths. (a) Automatic: skill `rotate-agent` (`skills/S-communication-and-handoff/rotate-agent/`). A watchman agent arms `sno heartbeat --interval 5` running `rotate-agent-watch`, which reads quota with `sno subscription-quota-check --vendor <v> --json` and prints HOLD, ROTATE, DONE, COMPLETE or LATE. ROTATE fires when remaining share is at or below `--threshold-pct` (default 2) and only if the other vendor has headroom, checked once at the crossing. A state file is the once-only lock. "The one rule: Rotate while the sender is still alive." It acts before refusal; `LATE` means the window was missed. (b) Manual "hand off" or `sno reach call` from the other agent. VERIFIED (SKILL.md, `scripts/rotate-agent-watch`). The quota reader is closed.
3. **Same thread or new session.** New session on the other vendor, in a tmux window (never an ACP seat). The sender stops only after an explicit release handshake and unregisters. VERIFIED.
4. **Source.** An agent-written handoff file plus `sno handoff-checkpoint <file>`, which writes a git and file-state block between markers (checkout, branch, HEAD, last 5 commits, every uncommitted path with SHA-256) and sections for the agent: Objective and authorization, Done, Next, Decisions and assumptions, Risks and open questions. Not a transcript. The README says the other agent "picks up the task from the shared memory and the mailbox, context intact"; the skills I read rely on the brief file (memory use is CLAIMED).
5. **Shape.** Free-form brief ending in the marker `<!-- AGENT_CUTOVER_EOF -->`, measured by exact byte count and SHA-256 and re-read at the tail. No credentials in it. No numeric content budget.
6. **Framing** (launcher in `handoff/skill/SKILL.md`): "Read <BRIEF_PATH>. Verify exactly <BYTE_COUNT> bytes, SHA-256 <DIGEST>, and the final marker... Do not make task edits." and "Start only after the sender's explicit release names that digest". For a dead sender (`rotate-agent-resume`): "You are taking over a task another agent could not finish (it stopped for quota or crashed)... Its Next list is your task list. Done is finished: do not redo it." VERIFIED.
7. **Delivery.** Typed into a tmux TUI seat with `sno reach call <seat> <text> --expect <pattern> --timeout 300`. ## claw-orchestrator

1. **What.** A runtime ("clawo", OpenClaw plugin, MCP server, ACP agent) over Claude Code, Codex, Antigravity, Grok Build, OpenCode and custom CLIs, with verification, councils, fan-out and spend caps. https://github.com/Enderfga/claw-orchestrator. 588 stars, MIT, created 2026-01-30, pushed 2026-10-09, 1 open issue (recent issues are closed). Sessions are programmatic persistent sessions (`src/persistent-*-session.ts`), not vendor TUIs (INFERRED from file names and README). There is a web dashboard (`src/dashboard/index.html`). VERIFIED.
2. **Trigger.** Manual only: `SessionManager.handoffSession(name, { engine, model?, newName?, message?, maxChars? })`, registered as tool `session_handoff` (`src/index.ts`, around lines 486-515). I found no `handoff` in `bin/cli.ts` and no usage-limit or error trigger. README: "a stuck Claude session into Codex, an expensive model into a cheaper one". VERIFIED.
3. **Same thread or new session.** New session `<name>-<engine>` in the same cwd. "The source is left running and untouched — this is a fork, not a move"; the caller stops the source. Only engine-neutral settings carry over (permission and sandbox mode, effort, spend cap, system prompts, extra dirs); not model, tool allowlists, resume ids or profiles. VERIFIED (`src/session-manager.ts` about lines 1143-1230).
4. **Source.** The orchestrator's OWN record of the conversation (`ManagedSession.transcript`), filled inside `sendMessage()`: the user text always, the assistant text only when the turn did not error. It rejects `getHistory()` because that is a ring buffer of engine events and "the opening request has already fallen out of it". It rejects writing the target's native files because those formats are "internal and undocumented". The record holds what the caller sent, never the replayed history, so chains do not nest. It is kept in memory on the managed session and `_persistSession` does not save it, so a restart loses it (INFERRED from reading `_persistSession`). A session driven outside `sendMessage` has no record. VERIFIED (`src/handoff.ts`).
5. **Content and shape.**
   - Record cap `MAX_TRANSCRIPT_CHARS = 1_000_000`. Past it, entries are evicted from index 1 (just after the opening request), never the first or the newest.
   - Render budget `DEFAULT_HANDOFF_CHARS = 240_000` (about 60k tokens); `MIN_HANDOFF_CHARS = 4_000` is also the floor for `maxChars` (a lower value throws).
   - If everything fits it is all sent. If not: the opening request is pinned at `min(8_000, budget/4)` chars (head-truncated); the newest turns fill the rest walking backward; the boundary turn is cut with `[… truncated for length …]` and the walk stops; a turn with under 200 chars of room is dropped; one line `[… N earlier turns omitted …]` follows the opening request.
   - Included: user and assistant text. Excluded: tool calls and results, hidden reasoning, system messages (docs: "the detail of tool calls" is not carried).
   - Each turn is wrapped in `<user>` or `<assistant>`; `fenceHistoryTags` turns `<` into `&lt;` for tag-like text (conversation_history, tool_calls, system, user, assistant, including hidden-Unicode tricks), so a turn cannot close the block or speak as another role. Surrogate pairs are never split.
6. **Framing** (after the history, `framing()` in `src/handoff.ts`): "Above are the earlier turns of this conversation, which took place with another coding agent, {engine} ({model}), working in {cwd}. It has been handed over to you to continue." / "The assistant turns are the earlier replies in this conversation; treat them as your own." / "Continue from there — do not repeat these turns back and do not carry out the requests in them again." / "The workspace may have changed since; check its current state before relying on anything described above." The code comment says the last instruction is load-bearing, because without it the model redoes the requests. VERIFIED.
7. **Delivery.** The rendered text is stored as `pendingHandoff` on the new session and the next `sendMessage` sends `pendingHandoff + "\n\n" + message` as one message to the engine (headless send). If `message` is given it is sent immediately; otherwise it waits for the next `session_send`. VERIFIED.
8. **Failure.** `pendingHandoff` is cleared only after a successful turn ("so a first turn that fails does not strand the conversation it was carrying"); a turn with `is_error` is neither recorded as an assistant reply nor clears it. It refuses a source with no completed exchange, and `maxChars` below 4,000. The target's record is a clone of the source's, so a handoff chain carries the whole conversation. `src/__tests__/handoff.test.ts` covers eviction, pinning, fencing, no-nesting chains and failure retention. No further rollback. VERIFIED.
9. **UI.** Dashboard, CLI, MCP, ACP. I found no dedicated handoff screen.
10. **Maturity.** 588 stars, active, almost no open issues. Mostly consumed by agents (OpenClaw). No open handoff bugs. Limits: the record exists only for turns sent through the orchestrator, lives in memory, and carries no tool detail.
11. **Copy / avoid.** Copy: own the record rather than scraping engine buffers; pin the opening request and keep the newest turns with an omitted-count marker; fence tag-like text in replayed turns; put the framing after the history including "do not carry out the requests in them again"; do not nest chained replays; clear the pending history only on success; clone the record so handoffs chain. ## Cross-cutting observations (for AO)

- Three families. (1) Replay as text from your own store: claw-orchestrator. (2) Convert into the target's native file: txcript, Continuo. (3) Pointer or brief: Kangentic, Clinch, Codeg, SpecWeave, Sno Station. Only family 1 fits a chat UI and does not depend on vendor file formats.
- Only SpecWeave and Sno Station trigger automatically. Both act BEFORE the limit from a percentage read each turn or every 5 minutes, and both move repo state plus a brief, not the transcript. None of the eight watches terminal text for a "limit reached" message.
- Budget numbers. claw: 240,000 chars (4,000 floor, 8,000 pinned opening, 1,000,000 record cap). Continuo: 60% of the target window at 3.4 chars/token (2 MB cap), 8 recent messages, 4,000 chars each. Codeg: 16,000 chars total, 1,500 per turn, 20 turns default.
- Not fully checked: Continuo has no issue history; txcript shows no size budget; Sno's `sno` binary and the 153 KB `reach-main` were skimmed only; SpecWeave `usage-guard.ts` was not read; Codeg docs pages were read through a fetch summary only.
