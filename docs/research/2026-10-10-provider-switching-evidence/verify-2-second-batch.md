## Terminal-TUI in-place switching

Question: does the in-place switch work when the agent is a raw TUI in a PTY, or only for structured sessions?

- Jean: structured only. Claude is spawned as `claude --print --output-format stream-json` (`jean-core/src/chat/commands.rs` ~L8006-8010, `claude.rs` ~L689-693) and Codex runs on an app-server, so there is no TUI to hand off. Jean's terminal pane is a plain shell.
- Kanna: structured only. Claude via `@anthropic-ai/claude-agent-sdk` `query()` (`src/server/agent.ts` L965), Codex via app-server, Cursor/Pi/Grok via per-turn CLI or SDK. `TerminalPane` and `TerminalWorkspace` are separate shell panes, not agents.
- Agent of Empires: the context-carrying switch is ACP only (`/acp/switch-agent`, a worker restart plus event-log recap). Terminal (tmux) sessions do have an in-place tool swap through the restart dialog (`Instance::swap_tool`, `src/session/instance/merge.rs` L139-184), but it carries NO conversation across different agents. Per `docs/guides/session-resume.md` L110-116 it "parks the outgoing agent's conversation... and starts a new one". Only a same-agent account swap (Claude, `src/session/conversation_carry.rs`) copies the transcript. Same-agent terminal-to-structured toggling keeps a Claude conversation only when a shared native store resolves (`docs/structured-view.md` L116).
- Kandev: structured only. Dynamic routing is defined over "downstream ACP sessions" (design doc L313-325) and always starts a fresh ACP session. Kandev does have separate CLI-passthrough (PTY) sessions, but I found no passthrough handling in `dynamic/*`, `dynamic_resolver.go` or `dynamic_launch.go`. Treat PTY candidates as unsupported or untested (not explicitly rejected in candidate validation).
- Helix: structured only. It is gated on `AgentType == "zed_external"`; the agent runs inside Zed's agent panel (ACP) and config hot-reload creates a new Zed thread (`session_switch_agent_handlers.go` L3-12, L90).
- Happier: REFUTES the belief. Happier runs Claude's real TUI in a terminal host (`apps/cli/src/backends/claude/unifiedTerminal/*`, which injects prompts and reads screen state), and the in-session agent switch works on it: the issue #332 repro switches a Codex session to Claude with the unified terminal runtime on. The seed was lost there; commit 50d6a168 (2026-08-30) fixes it by injecting the replay seed into the first terminal prompt. The stop path also has a terminal-host disposition (`terminal_host_adapter_unavailable`, coordinator L683-690). Caveat: this is injected-prompt handoff into a TUI, and it is limited to Claude's unified terminal (other agents there are SDK/ACP).

Net: of the six, five are structured-only. AoE offers a terminal tool swap with no handoff. Happier is a counterexample that hands context into a TUI session in place. Thus "almost nobody does it" holds for 5/6, not for Happier.
