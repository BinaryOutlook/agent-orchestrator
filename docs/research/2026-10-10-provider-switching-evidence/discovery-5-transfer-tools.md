### 1. OpenAI Codex first-party importer (`codex-rs/external-agent-migration`)

- Repo: github.com/openai/codex (128,531 stars, pushed 2026-10-10, Rust). Source files read: `sessions/export.rs`, `records_cla.rs`, `records_common.rs`, `append.rs`, `ledger.rs`. The long-form write-up of the whole crate is in `docs/codex-external-agent-migration.md` of harness-convert (secondary source; line refs there target Codex revision 2b5bdcf, 2026-08-02).
- Direction: Claude Code (and Cursor via `records_cur.rs`) into Codex only. One-way. (V src: both record formats `SessionRecordFormat::Cla/Cur` in export.rs.)
- Source of context: `~/.claude/projects/<proj>/*.jsonl`, one level deep, newest-K by mtime, 30-day default age, 50 sessions default; cwd read from inside records, session dropped if cwd missing or deleted (I: from secondary doc; V src that cwd=None returns Ok(None)).
- What it extracts (V src records_cla.rs:175-176, records_common.rs): only `type` in {user, assistant}; drops `isMeta` and `isSidechain` records; `thinking` blocks dropped (records_common.rs:37); `tool_use` becomes `[external_agent_tool_call: name] ... [/external_agent_tool_call]` text with description/command/file or truncated input; `tool_result` becomes `[external_agent_tool_result]` text, truncated; a user record that is only tool results is relabelled assistant. Unknown block types become `[external unsupported block: type]`. Caps are `NOTE_MAX_LEN` / `TOOL_RESULT_MAX_LEN` constants (values 2000/4000 per secondary doc, I).
- Shape: full replay of the flattened list, no summarising or clipping of older turns. Synthetic turn structure `external-import-turn-N` (TurnStarted, UserMessage event + user ResponseItem, AgentMessage event + assistant ResponseItem), then one extra AgentMessage `<EXTERNAL SESSION IMPORTED>`, a TokenCount fabricated from byte count, TurnComplete (V src export.rs). Leading assistant messages with no open turn are dropped.
- Delivery: creates a real Codex thread through the app-server (not file copy), backdated to original timestamps; `ThreadHistoryMode::Legacy` (V doc, consistent with transession writing `history_mode='legacy'`). Content-hash ledger at `~/.codex/external_agent_session_imports.json` (V src ledger.rs has `content_sha256`). Incremental append of only the new suffix when the model-visible transcript of the destination is a strict prefix; any `ContextCompacted`, `ThreadRolledBack`, `Compacted` in either side aborts the append (V src append.rs:243-272).
- Maturity: shipped in the product with tests (`*_tests.rs` for every module). One-way, so it cannot serve a Codex -> Claude switch, and the import is bulk "migration" not a "continue this task now" flow.
- Lessons for us: OpenAI itself chose to flatten tool structure into prose instead of replaying `function_call` items, which removes the orphan-tool-call problem; they also add an in-band marker so the UI and later appends can tell imported history from native.

### 3. casr (Cross Agent Session Resumer)

- Repo: github.com/Dicklesworthstone/cross_agent_session_resumer, 122 stars, pushed 2026-09-22, Rust, 3 open issues (installer hash verification, crate release qualification). Created 2026-02-08. Source read: `src/providers/codex.rs`, `claude_code.rs`, `src/pipeline.rs`.
- Reads/writes: read 17 providers, write most of them (OpenCode only legacy DB; Antigravity read-only). Aliases `cc`, `cod`, `gmi`.
- Mechanism (V src + readme): provider auto-detect by session id -> reader -> `CanonicalSession` (messages with role, content, tool_calls, tool_results, per-message `extra`) -> validation (hard error if empty or one-sided; at least 1 user and 1 assistant) -> optional enrich -> writer -> atomic temp+fsync+rename -> read-back verification, rollback on failure. `--force` makes a `.bak`.
- Codex writer (V src codex.rs:255-370, 745-880): path `~/.codex/sessions/YYYY/MM/DD/rollout-<ts>-<id>.jsonl`; `session_meta` line with both `id` and `session_id`, `cwd`, RFC3339 string timestamps, `originator: "casr"`, `model_provider: "openai"`, `source: "cli"`, `thread_source: "user"`. User text becomes `event_msg/user_message`; assistant becomes `response_item/message` with `output_text`. Reasoning text is emitted only as `event_msg/agent_reasoning`. Then registers the session in `~/.codex/state_*.sqlite` `threads` by introspecting `PRAGMA table_info(threads)` and refusing (non-fatal warning) if a required column cannot be populated, because "Codex does not resume from a bare JSONL file". Note: tool calls are written as Anthropic-style `tool_use`/`tool_result` blocks inside `message` content, not as native `function_call` items (V src codex.rs:840-860; I: that is non-native, whereas transession/hc write real `function_call` items).
- Claude writer (V src claude_code.rs): `~/.claude/projects/<dir-key>/<uuid>.jsonl`, entries with `parentUuid` chain, `sessionId`, `isSidechain:false`, `userType:external`, `version:"casr"`, `gitBranch:"main"` hardcoded; coerces `tool_use.input` to a JSON object (Codex stores args as strings).
- Enrichment (V src pipeline.rs:198-262): off by default; prepends two synthetic system messages: a conversion notice ("some provider-specific context may have been lost", original id, message count, workspace) and "Recent conversation snapshot" of last 4 messages x 180 chars.
- Handling of encrypted/compacted: no compaction logic found in the paths I read (I; grep for compact/encrypted in codex.rs found only reasoning event). Whole history is replayed, so very long sessions may exceed target context.
- Problems (V issues): store-format drift (OpenCode 1.x and 2.x schemas each produced "0 sessions" bugs, now closed), installer supply-chain items open. Active, fast-moving, single-author.
- Class A.

### 4. harness-convert (`hc`)

- Truncate (V readme): `hc truncate 20` clips the largest tool payloads (inputs and outputs) until N% freed, never conversation text, drops `view_image` payloads, new deterministic id so re-runs upsert. Motivated by their measurement that payload concentration is extreme (41 Codex records >200 KB = 45.9% of payload).
- Class A. The most instructive "how to make a native-resumable Codex file" notes among the small tools.

### 5. transession (+ codex2claude plugin)

- Tested compatibility pinned in README: Codex CLI 0.147.0 and Claude Code 2.1.234, both directions, verified by resuming in the target CLI.
- Mechanism (V src): IR `UniversalSession { ir_version "transession/v1", metadata{session_id, cwd, git_branch, model, platform_version, extra namespaced per platform}, events[] }`; events are Message, Reasoning(summary), ToolCall, ToolResult. Codex writer emits `agent_reasoning` event plus a `reasoning` response item with `summary_text`, real `function_call` and `function_call_output` items (codex.rs:456-520), and registers the thread in `state_5.sqlite` (`register_thread_in_sqlite`, sets `history_mode='legacy'`, lowercase provider id). Stamps the file with the installed CLI version (`codex --version`).
- Delivery (V src cli.rs:271-276): by default spawns `codex resume <id>` or `claude -r <id>` immediately (`--no-open` to skip), `--output <DIR>` writes into a throwaway home with credentials linked.
- Not preserved (V readme): opaque reasoning payloads, token accounting, Codex paginated `item_completed` items, shell snapshot sidecars, Claude subagent trees, tool-result sidecar directories.
- `MisterBrookT/codex2claude` (7 stars, Python) is a Claude Code plugin `/import-codex` that shells out to transession and then "normalizes" output for Claude (fixes Codex content tags, image sources, picker title, missing native fields) with a dedup ledger `~/.claude/codex-import-ledger.tsv` (V readme). Note: the slash command costs one model turn; they ship a shell script for zero tokens.
- Class A.

### 6. claude-code-tools `aichat` session porting

- Repo: github.com/pchalasani/claude-code-tools, 2,013 stars, pushed 2026-10-09, Python (PyPI). Listed in awesome-claude-code. The porting feature is one module family among many (voice, tmux, Codex server). Source read: `port_claude_to_codex.py`, `port_codex_to_claude.py`, `port_codex_flatten.py` (constants), docstrings.
- Direction: Claude <-> Codex. Output: native Codex rollout with Codex's own filename convention, atomic temp+rename, plus an entry appended to Codex `history.jsonl`; Claude session under `projects/<encoded-cwd>/`.
- Flattening policy (V src docstrings): user text and assistant text kept verbatim, never truncated; thinking and encrypted payloads dropped; tool_use flattened to `[claude tool call] name(args)`; tool_result flattened to `[claude tool result] ...` as assistant items; tool text capped at `TOOL_TEXT_CAP = 1500` chars with explicit suffix. Noise stripped: sidechain lines, command wrappers, task notifications, `<system-reminder>` blocks (provenance-based: whole-item reminders dropped; terminal reminder block peeled off tool output only when it matches a known signature).
- Compaction awareness (V src, the best treatment I found): both sources are append-only logs that still hold pre-compaction history the live model no longer sees. Claude -> Codex: if `isCompactSummary` lines exist, drop everything before the LAST one and start from that summary. Codex -> Claude: drop everything before the last `compacted` record and start from its `replacement_history` (preserved user messages; the encrypted summary item is dropped); legacy `compacted` with plaintext `message` becomes a user message. Reason recorded: a real 108-compaction rollout otherwise produced a ~6M-token transcript that could never be resumed. Codex per-turn re-injected `<codex_internal_context source="goal">` messages are dropped except the last, kept as `[codex goal context]`.
- Memory: two streaming passes, constant memory proportional to largest record.
- Class A (native, flattened).

### 7. sctxx and ccompactor

- Repos: github.com/handyutils/sctxx (19 stars, pushed 2026-09-11, Rust, Apache-2.0, npm + crates) and github.com/ccompactor/ccompactor (21 stars, pushed 2026-09-14, TS, MIT; README says "same idea as sctxx in TypeScript"). Both very new (Sept 2026). Source read for sctxx: `adapters/codex.rs`, `cli/handoff.rs`, `agents/seeding.rs`, `pipeline/render.rs`, README.
- Reads: Claude Code (rewinds, compaction boundaries, subagent transcripts), Codex (`~/.codex/sessions` and `archived_sessions`, `.jsonl.zst`, rollback replay, `apply_patch`), Pi. Hand off to claude/codex/pi.
- Mechanism (V src): canonical event IR; Codex adapter replays `thread_rolled_back` so the active branch is correct; `compacted` records: "a local compaction keeps readable replacement text; a hosted one is encrypted and only marks the boundary" -> `NativeCompactionSummary` or a bare `native_compaction` System event; `window_number` distinguishes windowed compaction from legacy history reset; `reasoning` with no readable text is marked `redacted`. Deterministic ledgers (files, commands, errors, commits), constraint extraction that quotes the user's own words verbatim and verifies quotes against the transcript, reconciliation with the working tree via read-only git (marks items stale/contradicted), secret redaction before and after any model call. Optional LLM "fold" (`--llm none|auto|cli:*|api:*`); `--model-context` checks the prompt fits before sending.
- Shape: layered artifact, default budget 8,000 tokens (L0 brief must fit "on a screen"), items emitted in priority order until budget; omitted items are named; `expand <ref> a..b` pages exact raw events back by `[evt a-b]` pointer.
- Delivery (V src seeding.rs): "artifact travels as a path, never inline"; one-line pointer in argv; for Claude Code can use `--append-system-prompt-file`; validates the path first because Claude fails lazily and silently on an unreadable file; falls back to cwd-pointer route when the agent version is unverified; child spawned with argv vector, no shell.
- Claims: README benchmark (4 real sessions, 76 questions, self-reported): nothing 0%, recency tail 13%, artifact 25%, artifact plus retrieval 57%; on events from mid-session, only retrieval scored (23/40, others 0/40). ccompactor's README says it withdrew a published comparison with sctxx because question sets overlapped by only 3 of 21 (V readme). Treat numbers as author-run, not independent (I).
- Class A (brief + on-demand retrieval, no native resume). The most research-grounded design; heavy for our use.

### 8. OmniSession (`omni`)

- Repo: github.com/bvolpato/omnisession, 5 stars, pushed 2026-10-09, Rust, created 2026-07-27. Docs read: README, `docs/COMPATIBILITY.md` (last verified 2026-09-12), `docs/ARCHITECTURE.md`. Rust source not read (so mechanism claims are V readme/docs only).
- Reads/writes: Claude Code (>=2.1.220), Codex (>=0.146.0, "minimum-version app-server session import", fork via `codex fork ID`), OpenCode (official list/export/import CLI, tested 1.18.18), Pi, Oh My Pi, Grok (ACP import), Cursor IDE and Cursor Agent (SQLite/protobuf writer), Antigravity CLI, Hermes. Any-to-any.
- Transfer ladder (V docs): 1) same agent: native resume/fork; 2) native import through the target's own import interface; 3) version-gated private native writers with read-back; 4) "semantic handoff": fresh target session from a private file that quotes redacted history as untrusted context. "No transfer silently upgrades to a riskier mode"; on a terminal it asks (retry, fork in source agent, handoff file, cancel); non-interactive falls back to handoff automatically.
- Safety/shape (V docs): history only, never replay: tool calls and shell commands are historical records, approvals, hidden reasoning, permission state stay out; writers that declare support store complete call+result pairs as finished native tool records named `hist_<provider>_<tool>`, everyone else gets documentary text; redaction on index, handoffs, imports; native import is transactional (fresh id, read-back, exact rollback on Ctrl+C or failure); `omni inspect <session> --target X` reports what is preserved, summarized or omitted; provider compatibility manifest with minimum versions is the source of truth; large transcripts keep first and last 1 MiB with coverage marked partial.
- Class A. Closest philosophical match to what AO needs (explicit fidelity ladder, fail-closed), but 3 months old with 5 stars.

## Other noteworthy details (not top 8)

- **session-hub (Gateton)**: tiered budget (V readme): header ~1k chars, recent tail verbatim up to 26k, one line per older message, omitted count; tool output compressed to short preview in every tier ("90% of the bytes, least useful part"); oldest messages condense first, never the tail; 40k chars (~10k tokens) default; `sessionhub native <uid>` prints the verified native resume command or refuses.
- **agent-session-bridge**: "resume handshake" prepended as first message listing pending state (open tool calls, queued input) and conversion losses (V readme); six directed pairs live-verified on real installs 2026-07-28 with sentinel recall of both user and assistant turns, which is a good acceptance test.
- **yuzushi session-handoff**: handoffs are immutable records outside the workspace referenced by `handoff://project/handoff` through MCP; PreCompact hook writes a redacted pointer-only recovery checkpoint; managed launcher supervises `claude`/`codex` and auto-switches (V readme). Benchmark in README is tiny (Codex 9/9 tasks, Claude 1/1) so low evidence.
- **claude-to-codex**: selects exact active branch of the Claude conversation (not whole file), detects model changes mid-session, deliberately does not transfer source-model safety/refusal verdicts as guidance, and tells Codex to verify current repo state before acting (V readme).
- **lifeline**: only automatic trigger-based tool; PTY wrapper watches output for a real usage-limit message and then fires the handoff; therefore only works for sessions started through `lifeline <agent>` (V readme).
- **parcels**: documents the five per-agent session path layouts and how each sanitises cwd; Droid also needs an index entry (V readme).
- **cc-session-io**: library preserving unknown Claude record types through `UnknownRecord`, repairs tool pairing on import, documents a Bun/Node hash mismatch for project paths over 200 chars (V readme).

## Mechanism patterns

1. **Native transplant (write the target's own session file, then register it).** Used by casr, hc, transession, claude-code-tools port, relayport, ai-session-bridge, session-bridge, UniSessions, omnisession (some targets), codex2claude. Pros: `claude --resume` / `codex resume` shows full history in the real UI; no prompt size limit; tool cards render (hc writes `event_msg` cards). Cons: depends on private, drifting formats; Codex needs BOTH `response_item` and `event_msg` streams (hc) and a `threads` row in `state_*.sqlite` (casr, transession, session-bridge; missing/empty `model_provider` breaks resume per hc); tool-pair integrity must be repaired (hc synthetic results; cc-session-io); long histories overflow the new model (claude-code-tools 6M-token case); every tool pins a tested CLI version.
2. **Native import through the target's own API.** OpenAI's importer (app-server thread creation), omnisession (Codex app-server import, `opencode import`, ACP for Grok), relayport (`goose session import`, `opencode import`). Pros: survives format drift, the vendor validates. Cons: only exists for some targets and versions; Codex's own importer is one-way and lossy by design.
3. **Generated brief delivered by prompt.** cli-continues (inline or pointer), Hermes, passoff, sessionport, lifeline, claude-to-codex. Pros: works for any target including ones with no import path and for TUI-only agents, immune to store drift on the write side. Cons: argv size limits (`E2BIG`, issue #84), the new agent re-derives state, some prompts make the agent auto-continue (issue #69).
4. **Agent-authored handoff file.** `/handoff` skills (jensvanbellen, orzilca, hilsetapp, yuzushi, project-continuity, parcels' HANDOFF.md). Pros: captures intent, dead ends, gotchas that the transcript only implies; needs no parsing. Cons: requires a live, still-responsive source agent (not available at rate-limit death), quality varies, and nothing is verified.
5. **MCP pull.** session-hub, AMLink, yuzushi. Pros: no rewrite, tiered on demand. Cons: target must have MCP configured and be told to call the tool.
6. **Deterministic extraction + provenance + retrieval.** sctxx / ccompactor. Pros: verifiable, redacted, budgeted, mid-session facts recoverable via `expand`. Cons: complex; handoff delivered as a pointer file so the target must read it; no native resume.
7. **Trigger by terminal scraping / launcher.** lifeline (PTY output scan for usage-limit text), yuzushi managed launcher. Pros: automatic. Cons: only for sessions started under the wrapper.
8. **Same-agent relocation** (parcels, hc cwd relocation): D-class but reuses patterns 1 and 4.

Treatment of the hard parts across tools:
- Reasoning: dropped by Codex importer, hc, claude-code-tools, omnisession; summary text kept by transession and cli-continues (as "Key Decisions"); encrypted payloads dropped everywhere.
- Codex compaction: replacement_history respected only by claude-code-tools and sctxx; cli-continues surfaces plaintext summaries only; Codex importer refuses incremental append after any compaction; hc/casr ignore it (I).
- Tool structure: flattened to prose (Codex importer, claude-code-tools, cli-continues summary) vs. preserved as native items (transession, hc, omnisession for declaring writers) vs. non-native blocks (casr in Codex).
- Sidechain/subagent: dropped (Codex importer, transession, claude-code-tools) or summarised (cli-continues Subagent results).

## Ideas worth stealing

1. **Compaction-aware cut**: take the transcript only from the last compaction boundary (Claude `isCompactSummary` line; Codex last `compacted` record's `replacement_history`), as claude-code-tools and sctxx do; otherwise a compacted session dumps history the model never saw.
2. **Tiered budget with verbatim tail**: header (~1k chars), last turns verbatim, one line per older turn, explicit "N omitted" count (session-hub); compress tool output first (90% of bytes). Pair with cli-continues' per-message char cap and a "Source Fidelity" warnings section.
3. **Pointer, not inline**: write the brief to disk and pass a one-line pointer (sctxx, cli-continues `--reference`); avoids E2BIG and keeps the file re-readable by the new agent. For terminal agents prefer a pointer plus pre-validated path.
4. **Include the original transcript path and an `expand`-style retrieval route** in the brief. sctxx's own benchmark (author-run) found that without retrieval nothing answered mid-session questions.
5. **Close ragged tails**: synthetic error result for any unpaired tool call (hc), or never replay tool structure (Codex importer: prose only).
6. **If writing native files, copy the exact lessons**: Codex needs `response_item` plus `event_msg`, `session_meta` with non-empty `model_provider`, `state_*.sqlite` `threads` row (introspect schema, fail closed), `history_mode legacy`; stamp with the installed CLI version; write atomically; read back and roll back (casr, hc, transession, omnisession). Prefer the target's own import interface when it exists (Codex app-server import).
7. **Marker + idempotence**: in-band marker like `<EXTERNAL SESSION IMPORTED>` and a content-hash ledger so re-switching A -> B -> A -> B does not duplicate history; incremental append only when the destination is a strict prefix.
8. **Strip injected noise** before handoff: `<system-reminder>`, `<environment_context>`, AGENTS.md/CLAUDE.md blocks, `isMeta`, `isSidechain`, command wrappers, Codex internal goal context (keep the last goal) (cli-continues, claude-code-tools, Codex importer).
9. **"History, never replay" and "untrusted" framing**: label imported tool calls as historical, fence quoted history as untrusted data, redact secrets (omnisession, sctxx).
10. **Stop and report, do not auto-continue**: orzilca's `handoff-continue` briefs and waits; cli-continues issue #69 shows users dislike auto-resume. Make "continue automatically" an explicit option.
11. **Mechanical state snapshot appended to the brief**: branch, last commit, `git status`/diff (parcels, lifeline, Hermes); tells the new agent what is actually on disk; ask it to verify repo state before acting (claude-to-codex).
12. **Fidelity report before commit**: `omni inspect --target X` and session-bridge's plan screen show what will be preserved, summarized or omitted, and the conversion-loss notes can be placed in the handoff preamble (session-bridge "resume handshake" for pending tool calls and queued input).
13. **Active-branch selection and model-change awareness**: take only the active conversation branch (rewinds) and note source model changes (claude-to-codex, sctxx rollback replay).
14. **Acceptance test**: session-bridge verifies each pair by having the target quote a sentinel user turn and a sentinel assistant turn after resume. Cheap and decisive.
15. **Do not carry over source-model safety/refusal verdicts** as guidance (claude-to-codex).

## Gaps and caveats

- Usage evidence is thin: most tools are under 3 months old with fewer than 30 stars; the only mass-use ones are cli-continues (1.5k stars, stale since May), claude-code-tools (2k stars, porting is a side feature), and Codex's own importer. No telemetry or user reports beyond issues were gathered.
- Source read for: Codex importer (partial), cli-continues, casr, hc, transession, claude-code-tools port, sctxx. omnisession, session-hub, yuzushi, ccompactor internals, lifeline, Hermes were README/docs only. Hermes' pack contents and size limits not verified.

- Cursor/Gemini/Droid target writing is only evidenced by README claims (casr, omnisession, hc read-only for Cursor); I did not inspect those writers.
- No Windows or TUI-live behaviour was tested; nothing was executed.
- PyPI could not be searched; ACP defines `session/load` for one agent replaying to clients but no cross-agent transfer (V web fetch).
- Delegation-style plugins (Claude calls Codex for a subtask) were classified D from descriptions only.
