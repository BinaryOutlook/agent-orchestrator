# Provider switching: desktop, ACP, and terminal supervisors

Research snapshot: 10–11 October 2026. This is a supporting evidence report, not a claim that every product was installed or exercised with paid provider accounts. Public first-party documentation was checked; the strongest open-source implementations were also traced in source. Current `main` can differ from the latest downloadable release.

## What counts

- **Same app conversation:** one durable application thread keeps its history while the underlying native agent changes. This is the closest match to AO's intended experience.
- **Seeded continuation:** source history is explicitly transferred into a new target session/tab. This is real handoff, but not literally the same conversation identity.
- **Shared harness:** the application's own agent loop changes inference provider/model while retaining its history. Useful, but not equivalent to moving from native Claude Code to native Codex.
- **Unverified:** multi-agent support exists, but reviewed primary evidence does not establish transfer of an existing conversation between agents. This is not a proof the feature is absent.
- **Bound/single:** explicit provider binding or only one native provider.

## Deep trace: T3 Code

This is the strongest direct reference for AO's desired stable conversation experience. The current switch planner compares provider instance, model, continuation identity and adapter capabilities, then chooses keep, restart-and-resume, fresh target with handoff, or rejection. Old provider-thread records remain history rather than being repurposed as a different provider. It looks up the latest eligible target-provider thread within the same application thread. [Pinned planner](https://github.com/pingdotgg/t3code/blob/dacd2cb649eea06a00244bd181eb400735e923d5/apps/server/src/orchestration-v2/ProviderSwitchService.ts).

The orchestration path determines whether the target needs the whole available context or only runs missed since it last received context. A target with native continuation state can resume that thread and receive a delta. A new target needs a fuller portable handoff. This is an application-history/native-thread split, not conversion of a Claude native transcript into a pretend Codex native transcript. [Pinned orchestrator](https://github.com/pingdotgg/t3code/blob/dacd2cb649eea06a00244bd181eb400735e923d5/apps/server/src/orchestration-v2/Orchestrator.ts).

`prepareProviderHandoff` maps canonical turn items into historical messages, tracks run status/coverage, performs deterministic history selection and stores the result as a ready handoff. Despite the field name `summaryText`, this path renders selected history; it does not ask the outgoing model to invent a summary. Delivery uses native history injection when supported, otherwise attributed context, and records delivery events. [Context preparation](https://github.com/pingdotgg/t3code/blob/dacd2cb649eea06a00244bd181eb400735e923d5/apps/server/src/orchestration-v2/ContextHandoffService.ts), [turn start/delivery](https://github.com/pingdotgg/t3code/blob/dacd2cb649eea06a00244bd181eb400735e923d5/apps/server/src/orchestration-v2/ProviderTurnStartService.ts).

User-facing policy: short histories can transfer intact; long ones prioritize recent dialogue, original request and useful activity outcomes. Selected messages remain attributed/full text, including partial failed or interrupted turns. Hidden reasoning, native tool state and attachments are not magically portable. The default allowance is 16,000, configurable within 1,024–64,000, with conservative UTF-8-byte accounting and a separate imported-byte cap. References to omitted history support later retrieval. This is not “latest native compaction plus exactly five final exchanges.” [Current handoff policy](https://github.com/pingdotgg/t3code/blob/main/docs/user/portable-handoffs.md).

Important version caveat: older discussions requested provider switching before the current V2 implementation. A feature request is not evidence of shipping. These findings verify checked `main` at `dacd2cb649eea06a00244bd181eb400735e923d5`, not a locally exercised release. Its design document is useful but should not be confused with proof that every documented fallback is implemented. [V2 design](https://github.com/pingdotgg/t3code/blob/dacd2cb649eea06a00244bd181eb400735e923d5/docs/orchestration-v2/provider-switching-and-context.md).

## Deep trace: Superset

Superset is a valuable TUI-oriented reference, but its UX is a new target split/tab with the source preserved, not one merged chat identity. The handoff dialog shows character count and estimated tokens. Its normal context limit is 36,000 transcript characters. It distinguishes another-agent continuation from same-agent native fork/resume. [Official feature guide](https://docs.superset.sh/agent-sessions), [CLI flags and limits](https://docs.superset.sh/cli/cli-reference).

Actual retrieval order is: adopt/find terminal session, try the active native harness binding, then recorded terminal-stream output, then a screen snapshot. A binding marked ended is not used as current native history. Parsing large transcripts happens off the main loop; unreadable/missing transcripts fall back rather than blocking continuation. Native transcript parsing is implemented for Claude and Codex in the reviewed source, not automatically for every terminal agent Superset can launch. [Terminal handoff retrieval](https://github.com/superset-sh/superset/blob/4ec5b6e287d380480a71b4b2ad98976354c82d4f/packages/host-service/src/terminal/terminal.ts), [native transcript reader](https://github.com/superset-sh/superset/blob/4ec5b6e287d380480a71b4b2ad98976354c82d4f/packages/host-service/src/terminal-agents/harness-sessions/transcript.ts).

Claude extraction reads JSONL user/assistant text and recognized queued-prompt attachments. Codex extraction reads message response items, keeps user/assistant text, and excludes recognizable setup instructions. Neither reviewed parser applies AO's proposed assistant-final-only selection or explicitly extracts a compaction artifact. A message labelled `summary` elsewhere must not be treated as proof of native compaction capture. [Claude parser](https://github.com/superset-sh/superset/blob/4ec5b6e287d380480a71b4b2ad98976354c82d4f/packages/host-service/src/terminal-agents/harness-sessions/claude.ts), [Codex parser](https://github.com/superset-sh/superset/blob/4ec5b6e287d380480a71b4b2ad98976354c82d4f/packages/host-service/src/terminal-agents/harness-sessions/codex.ts).

The prompt builder explicitly credits adaptation from Orca's `agent-session-fork-context.ts`. It strips terminal escape/control sequences, retains the newest bounded transcript, marks omissions, avoids splitting a surrogate pair, and picks a Markdown fence that cannot be closed by embedded backticks. The handoff frames history as untrusted data and tells the target to inspect current files/git rather than believe old output over disk. The transcript cap excludes surrounding prompt overhead, so 36,000 is not a strict total-bootstrap cap. It does not redact secrets automatically. [Pinned prompt builder](https://github.com/superset-sh/superset/blob/4ec5b6e287d380480a71b4b2ad98976354c82d4f/packages/shared/src/terminal-session-handoff.ts).

## Deep trace: 1Code

The implementation is simpler than T3's, but semantically different. `handleContinueWithProvider` refuses a running/reentrant/empty-source operation, exports the existing messages, writes a history file, creates another subchat in the same parent chat, opens it, and sets its provider. The source is retained. Direct provider mutation is separately refused once a conversation has messages. [Pinned active-chat implementation](https://github.com/21st-dev/1code/blob/9f1bc76fa4372c18c565b5a4f8daf38ae3595f0e/src/renderer/features/agents/main/active-chat.tsx).

Export uses user/assistant text and short recognized tool-call labels, with a 50,000-character tail budget and an omission marker at a paragraph boundary. Added header/omission text is outside that tail selection, so this is not a strict 50,000-character final artifact cap. This is transcript clipping, not provider-generated compaction. The file is written beneath the app's source-subchat pasted-text directory. The new subchat consumes the pending history file as an input attachment; the inspected path does not establish that merely switching automatically submits a fresh inference request. Moving text to an attachment does not remove its eventual context/token cost. [Exporter](https://github.com/21st-dev/1code/blob/9f1bc76fa4372c18c565b5a4f8daf38ae3595f0e/src/renderer/features/agents/lib/export-chat.ts), [file writer](https://github.com/21st-dev/1code/blob/9f1bc76fa4372c18c565b5a4f8daf38ae3595f0e/src/main/lib/trpc/routers/files.ts).

The repository was marked archived when checked. Treat this as a historical code pattern, not a maintained current product recommendation. [Repository](https://github.com/21st-dev/1code).

## VS Code, Conductor, and Happy: precise caveats

VS Code now explicitly distinguishes a language-model change from a harness change. Its official handoff docs promise history/context transfer, but allow initiating only from **Local** sessions; Agent Host sessions are destinations, not sources. Consequently this evidence does not prove round-trip switching between native Claude and Codex. The exact native serialization, budget and target-thread reuse were not source-audited in this investigation. [Harness guide](https://code.visualstudio.com/docs/agents/run/agent-harnesses). Its concepts page distinguishes independent peer chats from inherited-context forks and explicitly describes cross-harness handoff. Neither peer chats nor changing UI surfaces should be counted as provider switching. [Session concepts](https://code.visualstudio.com/docs/agents/concepts/sessions).

Conductor's official January 5, 2026 changelog is unambiguous about a new tab plus conversation summary. It does not establish an AO-like single canonical thread or native compaction import. Current support for additional agents should not be extrapolated into proof every provider pair uses the same handoff path. [Changelog](https://www.conductor.build/changelog/page/11), [agent modes](https://www.conductor.build/docs/concepts/agent-modes).

Happy changed substantially: the current shared Harness offers provider changes within a durable session, whereas the earlier `happy claude` / `happy codex` wrappers focused on remote/native sessions. The shared runtime uses Pi foundations. Its Codex path recreates Codex-oriented prompts/tools over Pi inference; the Claude path uses the official SDK for inference but replaces built-in tools/skills/settings with the shared harness's behavior. That is real continuity, but not an untouched native-CLI-to-native-CLI migration. [Happy overview](https://github.com/slopus/happy), [runtime architecture](https://github.com/slopus/happy-agent).

## Implications and ideas for AO

These are recommendations inferred from the evidence, not competitors' claims about AO.

1. **Keep AO session identity separate from provider-native thread identity.** T3 demonstrates the clearest version. Source/target markers in one timeline can make switching feel seamless without pretending native session formats are interchangeable.
2. **Use deterministic, bounded preparation on the switch path.** T3 selects history; Superset sanitizes and bounds a transcript; 1Code exports it. None of those paths needs to wait for the outgoing model to finish generating a handoff summary.
3. **Keep the agreed native-compaction artifact separate from generic activity summaries.** Store provenance/type/coverage. An activity's `summary` field can be a one-line event description. A field called `summaryText` can contain rendered transcript. Neither guarantees a compaction checkpoint. If the true checkpoint is unavailable, fallback policy should be explicit rather than relabeling another summary.
4. **Make the 32,000-character budget a total serialized-bootstrap budget.** Include headings, metadata, role labels, delimiters and omission markers before measuring. Superset and 1Code cap transcript content, leaving overhead outside; AO can avoid that ambiguity. Show users the approximate prompt size before switching.
5. **Preserve the user's final-response preference, but recognize its tradeoff.** Final-only history is compact. However, T3 intentionally preserves incomplete failed/interrupted work because the final answer can be missing. A small deterministic fallback for an incomplete turn is safer than silently claiming nothing happened.
6. **Native resume plus delta is an optional optimization, not a prerequisite.** T3 tracks delivered-run coverage. That can reduce repeated input on return, but introduces stale-native-state, duplicate-delivery and generation-fencing complexity. Given AO's production-LOC target, first make fresh-target bootstrap reliable; add resume/delta only with explicit measured value and focused tests.
7. **Keep workspace/git authoritative.** Superset's prompt says historical text can be stale. Carry cwd/worktree/branch and concise task metadata, then let the target inspect reality. Do not paste a giant file snapshot into every switch.
8. **Guard single-writer ownership and late events.** Release/detach old active native handles, reject switching while running, and fence events by generation. T3's public [native-session ownership issue](https://github.com/pingdotgg/t3code/issues/8259) illustrates the risk, not proof every current T3 switch is broken.
9. **Refresh the whole provider-dependent UI atomically.** Agent label, model list, effort, permissions and slash capabilities belong to the new provider. VS Code's harness distinction makes this especially clear; a stale Claude model selector after a Codex switch is a misleading state.
10. **Give terminal switching honest continuity.** A TUI cannot magically repaint another provider's native historical screen. AO can retain its own session timeline and inject the same bounded context into a new target terminal. Superset proves useful terminal continuation without demanding native transcript migration.
11. **Add omitted-history retrieval only if genuinely needed.** T3 supports references/readback; this is a stronger escape hatch than making every bootstrap enormous. It should be optional and audited for permissions, not a reason to exceed the simple first implementation.
