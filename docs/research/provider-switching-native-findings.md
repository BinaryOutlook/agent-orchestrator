# Native-agent provider switching: source findings

Research checked 2026-10-10–11. This is a supporting evidence notebook for the consolidated competitor analysis. Public documentation and selected source were inspected; no paid accounts, live model calls, or competitor end-to-end runs were performed. “Source verified” means an implementation exists, not that every direction works on every installed provider version.

## Classification rules

- **Same application thread:** one durable task/chat identity and visible history survive changing the executing provider. The target usually has a fresh native provider session.
- **Paired native sessions:** one application task groups a native session per provider and synchronizes context between them. Returning can resume that provider's existing session.
- **New-session continuation:** a new target session/tab receives a context packet or transcript pointer. Useful handoff, but not the same chat.
- **Transcript conversion:** creates a new target-native history file/database entry. Native-looking history is not transferred runtime state or a transferred prompt cache.
- **Delegation/document handoff:** another agent performs a subtask, or the user manually launches another tool and reads a document. Do not count this as seamless session switching.

## Synara: closest architectural reference for AO

Inspected main commit [`3e3e41c3b312ad95f62c33b155354b099bf36e2e`](https://github.com/Emanuele-web04/synara/tree/3e3e41c3b312ad95f62c33b155354b099bf36e2e).

### What stays stable and what changes

Current code supports a same-thread provider handoff; earlier descriptions limited to new-thread handoff are incomplete for this revision. `validateProviderHandoff()` refuses a starting/running turn, pending approval, pending user question, missing target, or same-provider instance/account handoff. Same-provider account handoffs still require a new thread. [Validation and rationale](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/orchestration/decider.ts#L149), [tests](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/orchestration/decider.providerHandoff.test.ts#L64).

The reactor checks for saved Claude sends and live background runtime tasks, explicitly clears the source resume cursor (which also stops source runtime), then starts the selected target on the **same Synara thread ID**. It registers prior-transcript bootstrap for this fresh session. The next turn receives context from Synara's own canonical messages. The source native cursor is deliberately abandoned, so switching Claude → Codex → Claude does not imply resuming the original Claude native thread. [Provider handoff reactor](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/orchestration/Layers/ProviderCommandReactor.ts#L6777), [clearSessionResumeCursor](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/provider/Layers/ProviderService.ts#L4653).

If target startup fails, it restores source model selection, appends visible failure activity, and marks the source's next fresh session for transcript bootstrap because its native continuation was already abandoned. This is an honest application-level recovery, not a claim the original native process never stopped. [Failure handling](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/orchestration/Layers/ProviderCommandReactor.ts#L6898).

Storage remains the same thread-keyed canonical stream/read model. SQLite includes `projection_thread_messages` (role, text, streaming, turn IDs, times), `projection_thread_activities` (kind, summary, JSON payload), and `projection_thread_sessions` (current provider/native IDs/runtime status). Later migrations extend these tables. Handoff caps apply to **prepared bootstrap**, not a six-message rolling deletion policy. [Foundational projection schema](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/persistence/Migrations/005_Projections.ts#L22).

### Exact bootstrap policy and the summary misconception

`handoff.ts` selects completed, nonempty user/assistant messages. It uses the last **six messages**, not six complete user/assistant exchanges, clipped to **2,400 characters each**. Older messages become up-to-**320-character snippets each**. Older snippets are retained from newest backward until the budget is used, reordered chronologically, with omission counts. Thread title, branch and worktree path are included. Whole transcript bootstrap has a **32,000-character ceiling**, and the turn builder may reduce that further to reserve room for current user input and other prompts. [Complete deterministic builder](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/orchestration/handoff.ts#L4), [turn-time budget allocation](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/orchestration/Layers/ProviderCommandReactor.ts#L3399).

**“Earlier conversation summary” is a label for deterministic clipped messages, not an LLM-generated synopsis and not a native compaction summary.** No model is called by this builder. It filters `thread.messages`; it does not read `thread.activities` or look for compaction checkpoints. Nor does its `streaming === false` test establish “assistant final answer only”: it accepts any completed assistant message in the canonical list.

The runtime activity field called `summary` is often just display text. For manual compaction it is “Context compacted manually”; for lifecycle events it becomes “Compacting context”, “Context compacted”, or a failure label. Provider-supplied detail/data may be retained in payload, but presence and semantic content are provider-dependent. That generic field is **not evidence a real compaction-summary body was captured**. Even if a provider supplies one in payload, this handoff builder does not consume it. [Compaction activity projection](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/apps/server/src/orchestration/providerRuntimeActivityProjection.ts#L1125).

The provider enum currently has ten kinds: Codex, Claude, Cursor, Antigravity, Grok, Droid, OpenCode, Pi, Devin and Oh My Pi. This is integration breadth, not independent live verification of all 90 directional handoffs. [Enum](https://github.com/Emanuele-web04/synara/blob/3e3e41c3b312ad95f62c33b155354b099bf36e2e/packages/contracts/src/orchestration.ts#L77).

**AO implication:** keep one AO session/canonical timeline and change runtime generation/provider binding. A distinct compaction-summary record must identify actual provider summary text, its covered-history boundary and provenance; do not infer it from a field named `summary`. The approved AO strategy (latest real summary plus recent full user/final-assistant exchanges within 32k) differs meaningfully from Synara's snippet algorithm.

## Tandem CLI: strongest native-TUI continuity reference

Inspected commit [`d5ff75e995085d06acb2ce05c414d51bb9099bdb`](https://github.com/Bhavya6187/tandem/tree/d5ff75e995085d06acb2ce05c414d51bb9099bdb).

Tandem creates one paired session with native IDs for two or three supported CLIs. The active provider runs in a real PTY. A file-tail synchronization engine normalizes entries and writes them into each shadow's **native** session storage, tracking per-direction cursors in `~/.tandem/state.db`. Returning resumes that paired provider's existing native session with mirrored intervening history. This produces native-TUI scrollback continuity, which a small bootstrap prompt alone cannot provide. [Architecture](https://github.com/Bhavya6187/tandem/blob/d5ff75e995085d06acb2ce05c414d51bb9099bdb/docs/how-it-works.md), [SyncEngine](https://github.com/Bhavya6187/tandem/blob/d5ff75e995085d06acb2ce05c414d51bb9099bdb/src/tandem/sync.py#L43), [switch_session](https://github.com/Bhavya6187/tandem/blob/d5ff75e995085d06acb2ce05c414d51bb9099bdb/src/tandem/ops.py#L110).

Ctrl-] arms a switch during active work, normally waits for a provider-specific completion boundary, gracefully exits source with bounded termination escalation, finishes synchronization, rotates provider and resumes target. Claude uses its session registry busy state; OpenCode uses database message state; Codex uses transcript/notify markers with documented fallback heuristics. This is not a hard idle guarantee across versions: older Claude without the registry can switch immediately mid-turn, while Codex can use quiescence/timeout fallback. Startup can overlap source teardown, but OpenCode is serial because its TUI caches session state on boot. If a target fails, the ladder tries another participant and eventually source. [Flip loop](https://github.com/Bhavya6187/tandem/blob/d5ff75e995085d06acb2ce05c414d51bb9099bdb/src/tandem/flip.py#L152), [boundary limitations](https://github.com/Bhavya6187/tandem/blob/d5ff75e995085d06acb2ce05c414d51bb9099bdb/docs/how-it-works.md#L49-L64).

Unlike AO's intended minimal packet, it translates completed tool call/result pairs to target vocabulary (`Bash`/`exec_command`, file tools/`apply_patch`, TODOs/`update_plan`). Unmappable activity remains verbatim, orphan results become commentary, unfinished calls receive placeholders, failed entries are quarantined. Text is tagged by source agent. Thinking is excluded. Compaction boundaries become generic notices, not a transfer of hidden compacted state. [Converter policy](https://github.com/Bhavya6187/tandem/blob/d5ff75e995085d06acb2ce05c414d51bb9099bdb/src/tandem/converter.py#L46), [Claude boundary parser](https://github.com/Bhavya6187/tandem/blob/d5ff75e995085d06acb2ce05c414d51bb9099bdb/src/tandem/harness/claude_code.py#L409).

No separate model inference is used just to synchronize, but resuming a different provider does not imply a transferable prompt cache or free processing of mirrored history. Native schema compatibility remains an ongoing maintenance cost. Its own documentation publishes tested CLI versions/ranges and storage-format observations. [Format observations and native reader checks](https://github.com/Bhavya6187/tandem/blob/d5ff75e995085d06acb2ce05c414d51bb9099bdb/docs/formats.md).

**AO implication:** borrow idle gating, provenance labels, explicit delivery/recovery and compatibility fixtures. Native transcript/tool rewriting is a separate, considerably larger feature if we insist on identical native-TUI scrollback; do not smuggle it into a five-thousand-line bootstrap implementation.

## Orca: fresh-session handoff, not same chat

Inspected commit [`7de3710dbed7466ebf0ff7edc84738ce9906c4f7`](https://github.com/stablyai/orca/tree/7de3710dbed7466ebf0ff7edc84738ce9906c4f7).

`prepareAgentSessionContinuationFromPane()` takes provider type, working directory, last prompt/assistant status and source transcript path. If a readable path exists it avoids serializing scrollback. Otherwise it captures the most recent 800 terminal scrollback lines. OpenCode SQLite candidate handles are excluded as directly readable transcript paths. [Preparation](https://github.com/stablyai/orca/blob/7de3710dbed7466ebf0ff7edc84738ce9906c4f7/src/renderer/src/components/terminal-pane/terminal-agent-session-continuation.ts#L49).

The user can choose focused or full mode. With a transcript path, focused mode tells target to start from status hints/current workspace and read relevant portions on demand; full mode tells it to read the entire transcript. Without a path, sanitized newest-terminal text is bounded at **36,000 characters** (capture cleanup itself is bounded at four times that). This is a cap on fallback transcript, not proof of a total prompt/token ceiling or a cap on the target's future reads. [Prompt builder](https://github.com/stablyai/orca/blob/7de3710dbed7466ebf0ff7edc84738ce9906c4f7/src/renderer/src/lib/agent-session-continuation.ts#L54), [fallback limiter](https://github.com/stablyai/orca/blob/7de3710dbed7466ebf0ff7edc84738ce9906c4f7/src/renderer/src/lib/agent-session-fork-context.ts#L1).

`launchAgentSessionContinuation()` checks target detection/enabled status, launches **a new tab**, delivers Claude context as draft and other agents after readiness, and reports launch/delivery failures distinctly. If PTY write happened without observed ready composer, it says delivery is unconfirmed and offers Copy Prompt. Source is explicitly read-only and unchanged. [Launch and failure reporting](https://github.com/stablyai/orca/blob/7de3710dbed7466ebf0ff7edc84738ce9906c4f7/src/renderer/src/lib/launch-agent-session-continuation.ts#L66), [dialog semantics](https://github.com/stablyai/orca/blob/7de3710dbed7466ebf0ff7edc84738ce9906c4f7/src/renderer/src/components/agent-session-continuation/AgentSessionContinuationDialog.tsx#L173).

Some source comments say “removed terminal handoff.” Those refer to old Chat/TUI lease ownership transfer, **not removal of this cross-agent continuation feature**. Do not confuse the mechanisms.

**AO implication:** use a bounded default packet plus optional read-only exact-history retrieval. Treat “process started”, “context written”, and “provider accepted context” as separate facts. A transcript pointer saves bootstrap size but does not cap eventual inference cost if target reads the whole file.

## Voyager/sessionFlow: canonical task index and budgeted continuation

Inspected commit [`ee86d8b079e927ea064a4860e0d6e87982d746b9`](https://github.com/HarryHeYu/sessionFlow/tree/ee86d8b079e927ea064a4860e0d6e87982d746b9).

This is now implemented, not merely an aspirational roadmap. Native session readers normalize evidence into a local SQLite index; a WorkThread groups multiple provider sessions. `switch`, `continue`, `handoff` and `merge` share `continuity.handoff_thread()`. It resolves task, snapshots git state, obtains a single-writer lease, chooses native resume or continuation bundle, and records a pending target attachment for the next scan. Direct targets receive a short prompt to read the bundle file. Missing direct launch path releases the lease and leaves a usable artifact. [Shared engine](https://github.com/HarryHeYu/sessionFlow/blob/ee86d8b079e927ea064a4860e0d6e87982d746b9/voyager/continuity.py#L1250).

Budgeting is deterministic and optionally goal-ranked. Presets are compact 4,000, balanced 20,000, full 100,000 **estimated tokens** (characters/4), with section-priority packing and omission notes. Absence of an explicit budget does not prove a universal hard cap. [Budget code](https://github.com/HarryHeYu/sessionFlow/blob/ee86d8b079e927ea064a4860e0d6e87982d746b9/voyager/budget.py#L1).

Optional transcript transplant writes NEW native text-only sessions. Only Codex and Grok writers are enabled; Claude is explicitly gated out due a timed-out probe, and hidden state/tools are dropped. [Writer gates](https://github.com/HarryHeYu/sessionFlow/blob/ee86d8b079e927ea064a4860e0d6e87982d746b9/voyager/writers.py#L1).

**Caution for borrowing:** the shared engine immediately returns native-resume if a previous target member is resumable. That branch itself does not attach a bundle containing intervening other-agent work. Startup-hook continuity exists elsewhere, so complete round-trip freshness needs route-specific live evidence; do not assume remembering the native ID automatically synchronizes missed work. [Resume branch](https://github.com/HarryHeYu/sessionFlow/blob/ee86d8b079e927ea064a4860e0d6e87982d746b9/voyager/continuity.py#L1354).

**AO implication:** one canonical data model and one switch service reused by UI/TUI/CLI; visible omission accounting; retrieve raw evidence only when needed. Avoid importing a general search/index/ranking system unless the simpler packet actually fails our needs.

## showagent: conversion with unusually honest compatibility boundaries

Inspected commit [`39a97bda8203314a0b3f43992b8da29c00d2cb21`](https://github.com/aytzey/showagent/tree/39a97bda8203314a0b3f43992b8da29c00d2cb21).

`Convert()` reads transferable user/assistant text, applies selected last-N scope, and invokes target writer. Default `MaxTurns <= 0` means all extracted turns; it is not a default five/six-message window. Codex/Claude writers mint new UUIDs and atomically write native files. Tools, approvals, attachments, reasoning and runtime metadata do not transfer. [Conversion and scope](https://github.com/aytzey/showagent/blob/39a97bda8203314a0b3f43992b8da29c00d2cb21/internal/session/handoff.go#L17), [new Codex ID](https://github.com/aytzey/showagent/blob/39a97bda8203314a0b3f43992b8da29c00d2cb21/internal/session/handoff.go#L159).

The project's [compatibility evidence](https://github.com/aytzey/showagent/blob/39a97bda8203314a0b3f43992b8da29c00d2cb21/docs/compatibility.md) separates source fixtures, native-reader checks and real model continuation. Its published evidence includes a Codex native-reader check of synthetic history; this should not be reported as all-provider live continuation. MCP returns resume commands rather than launching interactive providers.

**AO implication:** adopt this evidence discipline: fixture pass, native reader acceptance, UI display, context delivery and real model recall are different tests. Synthetic history must include UI display events as well as inference messages if we ever implement native conversion.

## Vibeyard: simplest transcript-pointer handoff

Inspected commit [`19bc19f0fac04f11e7d9e5cf68ed75ac7d291566`](https://github.com/elirantutia/vibeyard/tree/19bc19f0fac04f11e7d9e5cf68ed75ac7d291566).

`resumeWithProvider()` resolves source/profile, asks the source adapter for its transcript path, creates a **new** `SessionRecord` named with target suffix, and attaches a pending initial prompt. The prompt asks target to read full source transcript as read-only history; absent transcript asks the user to restate their goal. The pending prompt is transient and stripped from persistence, so this path is simpler but should not be assumed to have AO's durable handoff-retry guarantees. [Session creation](https://github.com/elirantutia/vibeyard/blob/19bc19f0fac04f11e7d9e5cf68ed75ac7d291566/src/renderer/state.ts#L820), [prompt builder](https://github.com/elirantutia/vibeyard/blob/19bc19f0fac04f11e7d9e5cf68ed75ac7d291566/src/main/providers/resume-handoff.ts#L18).

**AO implication:** keep the source/native binding exact, including account config-directory provenance. A short path-only prompt is easy to implement but sacrifices predictable context cost and degrades sharply when source transcripts are unavailable.

## Ideas to retain for AO

1. **Stable AO conversation, replaceable runtime generation.** Synara demonstrates UI continuity without rewriting every provider's internal transcript. This is the closest fit to the agreed scope and production LOC target.
2. **Typed context provenance.** Store real native compaction summary separately from generic activity labels and deterministic snippets. Record provider, native session/generation, covered event boundary, capture time, and whether text is complete. Preserve readable distinction between provider fact, user instruction and assistant claim.
3. **Bounded default plus exact-history retrieval.** Include approved latest summary and five recent exchanges/final assistant answers, exact context omissions, tiny workspace metadata. Keep full canonical history available read-only by an explicit path/API rather than implicitly replaying it.
4. **Round-trip test as first-class requirement.** Claude → Codex → Claude must recall a unique decision introduced only in Codex. This catches stale native-ID resume and double-bootstrap mistakes better than a successful switch toast.
5. **Observe delivery, not only launch.** Orca distinguishes unknown delivery from confirmed failure and offers the prepared prompt for recovery. AO should persist bootstrap acceptance separately from runtime start.
6. **Capability matrix, not multiplication marketing.** “Ten providers” does not prove 90 paths. Track read-history, real-summary capture, user/final extraction, native start, idle detection, context acceptance and round-trip verification separately per adapter.
7. **TUI continuity needs a deliberate choice.** Same terminal pane can host a new CLI, but identical historical native scrollback needs transcript synthesis/mirroring or an AO-owned timeline surface. Tandem proves feasibility; it also demonstrates why native tool translation should be a separate investment.
8. **Do not optimize bootstrap size by outsourcing unlimited reads.** Orca/Vibeyard file pointers make launch messages tiny, but full-read instructions can still incur large fresh inference inputs. Show prepared characters and estimated tokens, and make full-history reading optional.
9. **Reuse one command path everywhere.** Voyager's shared engine is useful: desktop chat, terminal UI and CLI should call the same daemon switch operation and expose the same idle/failure/idempotency semantics.
10. **Versioned fixtures before broad claims.** Borrow showagent/Tandem compatibility reporting. Pin representative provider formats and distinguish parsing acceptance from native UI rendering and real model continuation.

## Research limits and next evidence

Public source was fetched into temporary read-only research clones; competitor applications were not installed or run. No claim here establishes transferable server cache, hidden reasoning, permissions or in-flight tool state. Smaller packet/skill tools were verified through primary README behavior rather than a full code audit. Context-bridge deserves a dedicated source audit of its delta watermarks and acknowledgements before adopting linked-session reuse. Real round-trip and crash/retry tests remain required to certify AO's own product behavior.
